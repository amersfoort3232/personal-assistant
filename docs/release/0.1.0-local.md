# Personal Assistant 0.1.0 local release verification

Verification date: 2026-08-02
Target: Windows 10/11 x64, unsigned local development release

## Verified locally

- `npm run check`: passed (30 test files, 273 tests, plus TypeScript typechecking).
- `npm audit --omit=dev`: passed with 0 production dependency vulnerabilities.
- Playwright Electron E2E: passed (2 tests covering setup, editing, approval, restart privacy, and conflict reapproval).
- Production main bundle: contains no E2E fake module name, fixed-task marker, or placeholder test key.
- Release configuration: ASAR enabled, executable name `personal-assistant`, package commands pinned to x64, and the Squirrel.Windows maker restricted to `win32` with installer name `PersonalAssistantSetup.exe`.
- Renderer output: generated under the repository-root `.vite/renderer/main_window` tree included by Forge's package filter.
- Production package and ASAR inspection: passed against the generated Windows package.
- Packaged fuses: `RunAsNode`, Node options, Node CLI inspection, and browser-specific V8 snapshot loading disabled; cookie encryption, embedded ASAR integrity, and ASAR-only loading enabled. Electron 43 ships the generic `v8_context_snapshot.bin`, so enabling the browser-specific fuse would terminate the packaged app before startup.
- Squirrel install/uninstall smoke test: both commands exited successfully; shortcuts and application payload were removed, and the generated `.dead` residue was cleaned after verification.
- Rebuilt credentialed installer smoke test: silent installation exited successfully, and the installed `%LOCALAPPDATA%\personal_assistant\app-0.1.0\personal-assistant.exe` window remained responsive.
- Credentialed Google OAuth loopback smoke test: passed with the dedicated `personal-assistant-504317` Google Cloud project, an External/Testing Desktop client, the configured test user, and an encrypted refresh token written through Electron safe storage.
- Credential persistence smoke test: the production app remained responsive and wrote encrypted DeepSeek and Google credential files without storing either credential in the repository.

Electron Forge 7.11.2 requires `@electron/fuses ^1.0.0`, so the compatible package is pinned to 1.8.0 rather than the incompatible planned 2.1.2.

## Local error log

- Previous: `%USERPROFILE%\Documents\personal-assistant\personal-assistant.previous.log`

- Format: one JSON error entry per line with timestamp, process, operation, safe error fields, and bounded unexpected-error stacks.
- Excluded: prompts, IPC payloads, tasks, API keys, OAuth tokens, authorization headers, calendar content, HTTP bodies, command lines, and environment variables.
